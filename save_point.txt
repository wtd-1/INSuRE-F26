--- 4.4 Forward secrecy, goal M8 (mTLS PFS, server view) ---
Location: Mutations/investigations/C_m8_forward_secrecy/ (NEW)
  run_m8.py (quick: 32 checks; --long: 35 checks; last run 35/35 as
  expected), results.csv, README.md, run_long.log, models/, outputs/
  (108 MB; the largest files are 25-40 MB).
Diagnosis path (scratch runs, summarised in the README):
  1. -b 30 alone: still hits the step limit.
  2. Publishing certificates from key generation: still incomplete.
  3. Lemma chain on the unmodified protocol:
       L1/L2  exponents never leak;
       L3     DH value secret under M8's antecedent;
       10 derived-key forms (c/s hs keys, master secret, c/s ap keys,
       and the cat preimages).
     All HOLD on m0 (1.5 s); all VIOLATED on m6. M8 is still incomplete:
     CPSA puts listeners on derived keys of OTHER sessions.
  4. The search showed a client talking to itself as a server with its
     own key. Key-role separation rule (X.509 EKU) tried: still
     incomplete.
  5. PITFALL: the first separation rule used (p "client" z 1). Because F7
     makes both roles start with an identical key-load event, CPSA
     prefix-matching treats server strands as clients, and the rule
     pruned EVERYTHING (M8 "held" even on m6). Rules in tls13mtlspfs
     need height >= 2.
  6. Restated with server keys never disclosed, plus client-side lemmas
     (which need (non (privk ca)), or the adversary forges the cert):
     still incomplete.
  7. -r (younger nodes first): incomplete. CPSA must first know that x is
     honest, i.e. client authentication.
RESOLUTION by decomposition:
  M8 = (1) authentication before compromise AND (2) M8'.
  (2) M8' as a skeleton (server 6 + client 5 sharing all variables,
      including x and y as rndx; disclosure after server node 5; listener
      on response): NO SHAPES on m0 and on m6, 0.1 s.
      Controls on m0: without the listener there ARE shapes (the scenario
      is realizable); a listener on the disclosed key cpk IS found.
  (1) Inside tls13mtlspfs, using (fact undisclosed cpk) and the baseline
      rule undisclosed-not-disclosed:
        m0: INCOMPLETE (no counterexample; also with key separation,
            1,198 skeletons in 15 min);
        m6: VIOLATED.
      Its counterpart M2 in tls13-mtls: HOLDS for m5, VIOLATED for m6
      (answer key).
      Transfer argument, on paper and NOT checked by CPSA: cut the
      execution before the disclosure; the client key has never been
      sent; what remains is a tls13-mtls execution with cpk
      non-originating; M2 applies.
  => M8: HOLDS for m0/m5 (by decomposition), VIOLATED for m6/m8.
     Off-family M8 cells for m1-m4 remain UNDECIDED (leakage checks,
     not scored).
  The mentor still has to approve the transfer step.
